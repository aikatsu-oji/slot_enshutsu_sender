# Twitch 認証の取り方

`twitch/twitch_bridge.js` を本番の Twitch につなぐための手順。所要 5 分程度。

---

## 先に確認: そもそも認証が要るか

**コメント連動だけなら認証は要りません。** チャットは匿名で読めます。

```
node twitch/twitch_bridge.js --chat あなたのチャンネル名
```

アプリ登録も OAuth も不要で、これだけで動きます。使えるのは:

| | `--chat` (認証なし) | EventSub (認証あり) |
| --- | --- | --- |
| チャットのコメント | ○ | ○ |
| チャット連帯カウンタ / 初コメ歓迎 / 押し順投票 | ○ | ○ |
| チャンネルポイント | × | ○ |
| ビッツ / サブスク / ギフト | × | ○ |
| レイド / フォロー | × | ○ |
| 配信開始・終了の検知 | × | ○ |

**メダルの主軸はチャンネルポイント**なので、設計どおりに動かすなら認証が要ります。
以下はその手順です。

---

## 0. 配布された状態で使うなら、アプリ登録は不要

`twitch/client_id.js` に配布元のクライアント ID が入っていれば、**登録も設定ファイルも要りません**。

```
npm run twitch          →  ブラウザでコードを入れて承認  →  以降ずっと自動
```

チャンネル名も指定しなくて構いません。**承認した本人のチャンネル**が自動で使われます。

> **配布元にトークンは渡りません。** 公開クライアント + Device Code Grant なので、
> トークンは Twitch から利用者の PC へ直接発行され、配布元のサーバーは一切介在しません。
> クライアント ID 自体も秘密ではありません (ブラウザやアプリに埋め込まれる前提の値)。

自分のアプリで動かしたい場合、または `client_id.js` が空の場合だけ、次に進みます。

---

## 1. Twitch にアプリを登録する (1 回だけ)

<https://dev.twitch.tv/console/apps> を開いて「アプリケーションを登録」。
**承認する Twitch アカウントは配信者本人**である必要があります (自分のチャンネルの
サブスクやチャンネルポイントを読む権限を、その本人が与えるため)。

| 項目 | 入れる値 |
| --- | --- |
| 名前 | 何でもよいが **Twitch 全体で重複不可**。`slot-enshutsu-あなたの名前` など |
| OAuth リダイレクト URL | `http://localhost` (今回のやり方では実際には使わないが、必須項目) |
| カテゴリー | `Application Integration` |
| クライアントの種類 | **公開 (Public)** ← ここが重要 |

**「公開 (Public)」を選ぶ理由**: クライアントシークレットを配信 PC に置かずに済みます。
このプロジェクトは Device Code Grant を使うので、シークレットは不要です。

登録したら **クライアント ID** をコピーします。**クライアントシークレットは使いません**
(発行しなくてよい / 発行してもどこにも書かない)。

---

## 2. 設定ファイルを置く (自分のアプリを使うときだけ)

`twitch/config.example.json` を `.run/twitch_config.json` にコピーして埋めます。
`.run/` は `.gitignore` 済みなので、リポジトリには入りません。
**配布元の ID をそのまま使うならこの手順は不要です。**

```json
{
  "clientId": "コピーしたクライアントID",
  "channel": "あなたのチャンネル名"
}
```

`channel` は `twitch.tv/` の後ろの部分 (URL に出る英数字の名前) です。表示名ではありません。
**空のままでも構いません** — その場合は承認した本人のチャンネルが使われます。

環境変数でも指定できます (そちらが優先):

```
set TWITCH_CLIENT_ID=...
set TWITCH_CHANNEL=...
```

---

## 3. 起動して承認する

中継サーバーを起動した状態で:

```
npm run twitch
```

初回はコンソールにこう出ます。

```
[Twitch] 認証が必要です (初回、またはトークンが失効しています)

  ┌─────────────────────────────────────────────
  │ ブラウザで次の URL を開き、コードを入力してください
  │   URL : https://www.twitch.tv/activate
  │   コード: ABCD-EFGH
  └─────────────────────────────────────────────
```

ブラウザでその URL を開き、コードを入れて承認します。承認すると自動で先へ進み、
`.run/twitch_token.json` にトークンが保存されます。

> 承認画面には **`slot-enshutsu-idol-katsudo`** というアプリ名が出ます (同梱の
> クライアント ID を使っている場合)。これがこのプロジェクトのアプリです。
> 別の名前が出たら、`twitch/client_id.js` か環境変数が別の ID に差し替わっています。

**2 回目以降は何も聞かれません。** トークンは自動で更新されます
(期限前に更新、401 を受けたら 1 回だけ更新して再試行)。

うまくいくと:

```
[Twitch] 認証できました: あなたのチャンネル名
[Twitch] チャンネル あなたのチャンネル名 (id 123456789) として動きます
[Twitch] 購読を登録しました: 10/10 件
```

---

## 4. 要求されるスコープ

既定の `twitch/rules.json` では、この 5 つが承認画面に出ます。

| スコープ | 何のため |
| --- | --- |
| `channel:read:redemptions` | チャンネルポイントの引き換え (**メダルの主軸**) |
| `user:read:chat` | チャットのコメント (連帯カウンタ・初コメ歓迎) |
| `bits:read` | ビッツ (演出のみ) |
| `channel:read:subscriptions` | サブスク・継続・ギフト (演出のみ) |
| `moderator:read:followers` | フォロー (演出のみ) |

レイドと配信開始・終了はスコープ不要です。

### 使わないイベントのスコープは要求されない

**スコープはルール表から自動で決まります。** 使わないルールを消すか
`"enabled": false` にすれば、そのぶんの権限は求められません。

たとえばビッツ・サブスク・フォローのルールを消すと、承認画面に出るのは 2 つだけになります。

```
既定       : channel:read:redemptions / user:read:chat / moderator:read:followers
             / bits:read / channel:read:subscriptions   (5件)
絞ったとき : channel:read:redemptions / user:read:chat   (2件)
```

---

## 5. うまくいかないとき

| 症状 | 見るところ |
| --- | --- |
| `クライアント ID がありません` | `twitch/client_id.js` が空。配布元の ID を入れるか、自分で登録する |
| `チャンネルが見つかりません` | `channel` に表示名を入れていないか。URL の英数字名を入れる。空にすれば自動で本人になる |
| チャンネルポイントが反応しない | 起動ログの `[報酬]` 行を見る。報酬名が違えば「似た名前の◯◯があります」と出る |
| 一部だけ `購読に失敗` と出る | そのスコープを承認していない可能性。`.run/twitch_token.json` を消して再認証すると承認画面がやり直せる |
| `購読が取り消されました` | Twitch 側で連携を解除した / アプリを消した。`.run/twitch_token.json` を消して再認証 |
| フォローだけ来ない | `moderator:read:followers` は「自分のチャンネルのモデレータとして読む」権限。配信者本人で承認しているか確認 |
| 認証をやり直したい | `.run/twitch_token.json` を消してもう一度 `npm run twitch` |

**設定を変えるたびに再認証は要りません。** ルール表を増やしてスコープが増えたときだけ、
`.run/twitch_token.json` を消して承認し直します。

---

## 6. 秘密情報の扱い

- `.run/` 配下 (`twitch_config.json` / `twitch_token.json`) は `.gitignore` 済み。**リポジトリに入れない**
- **クライアントシークレットは使わない** (公開クライアント + Device Code Grant のため)
- トークンは配信 PC のローカルにだけ置く。共有・スクリーンショットに映さない
- 中継サーバーは既定で `127.0.0.1` だけを待ち受ける。`HOST=0.0.0.0` を付けるのは
  別 PC の OBS から見るときだけ (同一 LAN の誰でも遊技者操作を送れるようになる)
